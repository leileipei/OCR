# Umi-OCR 多人 Web 改造实施路线图

本路线图把已确认的系统设计拆成四个可以独立验收的实施计划。每个阶段结束后再编写下一阶段的细化计划，避免把未经验证的 E10 接口或 OCR 插件行为写成错误假设。

## 阶段 0：技术验证

验证三项前置条件：

1. Umi-OCR 插件可以脱离 QML 和桌面会话运行；
2. PDF 页面渲染、OCR 和可搜索 PDF 合成可以在 Windows 服务环境运行；
3. 当前 e-cology 10 实例能够通过官方支持的 SSO 接口提供稳定用户标识和部门信息。

输出：机器可读证据、资源测试数据和明确的继续/停止结论。

计划文件：[2026-07-13-umi-ocr-web-phase-0-validation.md](./2026-07-13-umi-ocr-web-phase-0-validation.md)

## 阶段 1：最小业务闭环

在阶段 0 通过后编写，交付：

- Vue 3 Web 界面和 FastAPI 服务；
- E10 登录及本地用户映射；
- PostgreSQL 数据库任务队列；
- 图片/PDF 上传、两个 OCR Worker、进度查询；
- 文本和可搜索 PDF 下载；
- 本人任务历史。

验收：5 名用户同时提交，任务不丢失、不重复，浏览器断开不影响执行。

## 阶段 2：企业权限与治理

在阶段 1 通过后编写，交付：

- 部门、项目、成员角色和对象级权限；
- 审计事件；
- 项目保留期限、30 天待清理区和合规保留；
- 系统管理页面。

验收：权限矩阵、安全越权测试、删除及审计抽查全部通过。

## 阶段 3：生产运维与上线

在阶段 2 通过后编写，交付：

- IIS/Windows Service 部署；
- 健康检查、指标、结构化日志和告警；
- PostgreSQL 及文件备份恢复；
- 安全加固、1,000 页负载测试和试运行。

验收：RPO 不超过 24 小时、RTO 不超过 4 小时，连续 5 个工作日无 P1/P2 故障。

## Git 约束

按用户要求，当前文档和后续执行不创建 Git 提交。所有阶段以测试结果、验证报告和工作区变更清单作为检查点。
